# SASD API Server – Code of Conduct

This project aims to provide a welcoming, professional environment for people contributing to a small open-source REST API server.

## 1. Expected behavior

- Treat contributors and maintainers respectfully, regardless of background, identity, or experience level.
- Discuss technical choices on their merits; explain assumptions, alternatives, evidence, and trade-offs.
- Welcome constructive feedback and be willing to revise decisions.
- Keep issues and pull requests focused on reproducible problems and documented requirements.
- Protect confidential data: no credentials, private keys, client records, or personal medical information in public discussions.
- Credit other people's contributions and respect third-party code and documentation licenses.

## 2. Unacceptable behavior

Harassment, discrimination, personal attacks, threats, deliberate humiliation, doxxing, and repeated bad-faith disruption are not acceptable. Publishing another person's sensitive information or credentials without authorization is also prohibited.

## 3. Reporting conduct concerns

Where possible, contact the repository maintainers through an available private channel without posting personal details publicly. If no private contact mechanism is visible, ask for a confidential contact path in a neutral message without describing the sensitive details.

Security vulnerabilities should be reported following [SECURITY.md](SECURITY.md) rather than this conduct process.

## 4. Scope and moderation

These expectations apply to project discussions, issues, pull requests, code reviews, and other project-related interactions. Maintainers may moderate or close discussions, reject contributions, or restrict participation when necessary to protect contributors or the project. Actions should be proportionate and based on behavior and available evidence.

## 5. Technical disagreement

Differences of opinion on architecture, performance, language features, security, and release scope are expected. Address disagreements through respectful review and, when appropriate, an [Architecture Decision Record](docs/adr/README.md). Decisions must be documented instead of resolved through personal criticism.

---
This is a project-specific conduct policy. It does not imply staffing, formal response-time commitments, or a dedicated moderation organization.
